# 0.1.1 验收记录

2026-09-08，Apple Silicon Mac、macOS 26.5.2、Xcode 26.5、Node 26.7.0。
使用独立 `TODOCUE_HOME`、独立 QA bundle ID 和合成文件，不修改日常任务数据库。
所有界面动作通过 Computer Use 的原生 macOS 控件完成；API/CLI 负责生成测试任务和核对实际保存状态。

- 全屏修复后的 `swift test --package-path apps/macos`：51 项通过。

- 主分支 push 与 PR 自动跑运行时和 Swift 门禁；版本发布在双架构原生 runner 重新测试，然后签名、公证。任一构建失败不公开 Release。

## Computer Use 验收

| 场景 | 结果 |
| --- | --- |
| 创建图文任务 | 文件选择器一次导入 4 PNG + 1 TXT，填写标题/备注并保存，详情实际有 5 个附件 |
| 图片排列 | 四图 2×2；编辑移除一图保存后变为三图横排；300pt 窄面板无横向溢出 |
| 原文件预览 | 图片 Quick Look 可读原图，文本 Quick Look 显示中文内容 |
| 粘贴 | 从 Preview 复制图片，点击粘贴图片，保存后显示新 PNG |
| 另存为 | 原生保存对话框导出 PNG，与上传前原文件 SHA-256 完全一致 |
| 编辑与草稿 | 移除后返回不提交删除，重新编辑保留草稿，保存后才改变附件 |
| 超限输入 | 10 MiB + 1 byte 文件被拒绝，显示文件名及大小错误，已有附件保持不变 |
| 并发写入 | GUI 草稿期间由 CLI 修改任务，GUI 保存提示已在别处修改，后台新内容没有被覆盖 |
| 深色外观 | 实际深色 QA 进程中图文网格、文字、文件卡片可读 |
| 外部写入/坏图 | API 添加未声明 MIME 的坏 PNG，SSE 自动刷新；显示无法生成缩略图的回退提示，界面继续工作 |
| 断线与重连 | 停止独立 runtime 后保留附件视图并禁用写入，重启 runtime 后自动恢复，并收到后续附件更新 |
| 真实 Cue | 设置真实到期提醒，由 scheduler → SSE → App 触发刘海卡片；可见 Cue 标志、任务名和操作按钮 |
| Cue 操作 | 点击完成后 API 状态为 done；点击延后后 reminderAt 约为 10 分钟后；点击标题打开正确任务详情 |
| 排队与收起 | 连续两个提醒依次展示；无交互约 9 秒收起；收起不完成任务 |
| 不抢输入 | 任务标题保持输入焦点期间触发其他任务提醒，按键继续写入原标题；后续观察到第二张排队卡片 |
| 刘海开关 | 关闭设置后到期事件仍提交到通知 sink，刘海不出现；恢复开关后正常出现 |
| 全屏安静 | 原生 Finder 进入全屏时实测发现安全区漏判；修复后再次到期，提醒 submitted，刘海保持 205×32 收起状态；Finder 窗口实际为 1728×1084、顶部 33pt |

自动测试里的系统通知使用内存 sink，避免制造桌面通知；其验证的是调度、去重和 SSE 分支。系统通知提交状态和实际桌面展示是不同的验收层。
减少动态效果通过确定性动画姿态及窗口零时长分支测试；未修改用户全局辅助功能偏好。旧 macOS 的运行环境与 Intel 真机 GUI 不在本机覆盖范围，两个架构的构建/Swift 测试由发布 CI 执行。
