# TodoCue v0.8.0

v0.7.1 之后的功能版本：macOS 通用版重新提供 Apple 日历与提醒事项同步，待办经 iCloud 同步到 iPhone。任务引擎、REST API、CLI、MCP 和数据库格式没有变化，数据目录与 v0.7.1 兼容。

## 下载与安装

- macOS 14+：Apple Silicon 选择 `macOS-arm64.dmg`，Intel 选择 `macOS-x64.dmg`。将 TodoCue.app 拖入 Applications，退出旧版后再打开。两个 DMG 均经 Developer ID 签名和 Apple 公证，并已 staple 公证票据。
- Windows：x64 选择 `Windows-x64-setup.exe`（Windows 10/11），ARM64 选择 `Windows-arm64-setup.exe`（Windows 11）。Windows 安装包没有做 Authenticode 签名，系统可能提示"未知发布者"；请只从本仓库的 Release 下载，并核对 SHA256SUMS。
- 从 v0.7.1 升级：直接用新安装包覆盖安装，数据会保留。

## 本版变化

- **Apple 日历与提醒事项同步回到通用版（仅 macOS）**：在设置 › 同步中，有「同步到日历」和「同步到提醒事项」两个开关，默认都关闭。
  - 打开后，有日期的待办会出现在 Apple 日历或提醒事项的「TodoCue」中，经 iCloud 同步到 iPhone。
  - 双向同步：在 iPhone 或 Mac 的日历、提醒事项里改期、改标题或勾选完成，TodoCue 会跟着改；在那边删除条目，约 10 分钟后对应任务也会被删除。
  - 推荐只开提醒事项：从 iOS 18 / macOS 15 起，带日期的提醒也会显示在日历里。
  - 仅在 TodoCue 运行时同步，不额外设置闹钟。
  - 同步规则与旧 SwiftUI 客户端相同，详见 [Apple 同步](https://github.com/NanmiCoder/TodoCue/blob/main/docs/apple-sync.md)。
- **从 v0.5.x 接着用**：沿用原来的同步开关、「TodoCue」日历或列表，以及已有的同步记录，所以已同步的条目不会再建一份。
  - 换用新客户端后，旧客户端留下的每条记录都会先做一次确认：在这条记录对应的条目被重新找到之前，条目找不到只会解除对应关系并重新创建，不会删除任务。所以没有运行 TodoCue 期间在手机上清理过的条目，不会让任务被删；iCloud 短暂读不到数据，也不会因此出现重复条目。
  - 如果 macOS 没有沿用之前给过的授权，同步页会提示「开关已打开，但还没有获得完整访问权限」，点「授权访问」即可重新申请。
- **不会两边同时写**：如果旧版 SwiftUI TodoCue 在运行，同步会暂停并在设置里提示，旧版退出后自动继续。

## 升级、边界与回退

默认数据仍在 `~/.todocue`（Windows 为 `%USERPROFILE%\.todocue`），支持 `--home` / `TODOCUE_HOME`。旧的 SwiftUI 客户端在运行时，通用版会提示先退出，避免同时操作同一份数据。

同步由 App 内置的辅助程序完成（`TodoCue.app/Contents/Helpers/TodoCueAppleSync`），macOS 把日历和提醒事项的访问权限记在 TodoCue 名下。后台服务不访问日历，所以退出 App 后不会同步。Windows 版没有这项功能。

本版仍不提供硬件刘海安全区适配，也不会自动导入旧版的全部偏好；依赖这些功能的用户可以继续使用 v0.5.3，指向同一个数据目录即可恢复旧客户端。

验证范围：
- 已在一台 Mac 上用隔离数据实测：授权记在 TodoCue 名下；在 iCloud 中创建「TodoCue」日历；TodoCue 中的改名约 4 秒后同步到日历，完成任务后对应的日程被删除。
- 从 Apple 侧回写到 TodoCue、旧版运行时暂停，目前只有自动化测试覆盖。
- 正式签名包能否沿用旧客户端的授权，以及接管已有同步记录，在发布前尚未在真机上验收。

不要在多台 Mac 上同时开启同步，否则同一个 iCloud 日历里会写出重复条目。
