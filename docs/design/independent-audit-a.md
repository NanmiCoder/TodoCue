# TodoCue 独立视觉审稿 A

日期：2026-09-07。观察范围：当前 macOS 原生面板的 11 张真实截图，340px / 300px、浅色 / 深色、今日、全部、详情、编辑、设置和快速输入状态。已逐张使用图像查看工具观察，并独立阅读对应 SwiftUI / AppKit 源码；未阅读既有设计评价或其他审稿人的报告，未操作 App、修改产品代码或真实任务。

**坦诚总评：现在的 TodoCue 干净，但还不够利落；圆角与留白做得比信息组织更充分，深色模式的明暗层级尤其拖累整体质感。**

以下没有发现足以仅凭这些截图判为 P1 的视觉阻断。P2 表示值得优先改进的日常阅读或一致性问题，P3 表示较低优先级的层级取舍。截图中的指针光晕和系统滚动条不作为产品缺陷。

## 1. P2 — 深色外壳过亮，中央内容像嵌入的黑槽

- **所见证据：** [09-today-dark-340.png](evidence/2026-09-07/09-today-dark-340.png) 与 [10-today-dark-300.png](evidence/2026-09-07/10-today-dark-300.png) 中，顶部导航和底部快速输入是明显的中灰，中央阅读面却接近炭黑；[11-quick-add-dark-300.png](evidence/2026-09-07/11-quick-add-dark-300.png) 输入区获得焦点后，底部这块亮灰区域更突出。与 [02-today-light-340.png](evidence/2026-09-07/02-today-light-340.png) 的浅灰外壳、较亮纸面相比，内容与外壳的明暗关系反了过来。
- **用户影响：** 承载工具栏和输入框的外层比任务区更抢眼。深浅色像两套不同的空间关系；深色容易产生厚灰边框包着黑色凹槽的观感，削弱轻巧的原生面板气质。
- **明确改法：** 先统一深色的三层明度关系：外壳保持最安静，阅读面只做轻微分离，下一步靠 mint 色相而非大幅明暗差突出。降低外壳与阅读面的明度落差，让快速输入与外壳接近，仅在焦点时使用细线强调。保留系统材质，但调整叠加在其上的深色 surface / insetSurface 色值与不透明度；修改后至少用明亮和深色桌面各截图一次。
- **性质与确定程度：** 明暗反转是截图可验证的问题，确定程度高；“灰框黑槽”及其质感影响属于品味判断，确定程度中高。截图没有展示完整桌面，不能据此断言所有壁纸下都同样明显。

## 2. P2 — 表单和设置缺少稳定的控件对齐线

- **所见证据：** [05-edit-light-340.png](evidence/2026-09-07/05-edit-light-340.png)、[06-edit-light-300.png](evidence/2026-09-07/06-edit-light-300.png) 的“任务属性”区域中，项目输入框与优先级控件在右侧，“预计 45 分钟”却换到下一行并退回卡片左边，形成三种起点；[08-settings-light-300.png](evidence/2026-09-07/08-settings-light-300.png) 的三个开关紧跟各自标签，横向位置随文案长短变化。
- **用户影响：** 属性不像一组可快速扫读的字段，更像逐个摆放的零件。窄面板本就需要频繁上下扫视，游移的控件位置增加找值、对比状态的负担，也让原生控件看起来缺少整体设计。
- **明确改法：** 编辑属性用稳定的两列布局，统一标签宽度；预计耗时单独成为完整的一行，输入框与项目字段的起点一致。设置开关行占满宽度，标签靠左，开关统一靠右。继续使用原生输入框、选择器和开关，先解决排列，不必重画控件。
- **性质与确定程度：** 对齐不一致可直接验证，确定程度高。建议的具体列宽属于实现选择，需在 300px 和 340px 同时验证。

## 3. P2 — 最小宽度下，下一步的元信息在语义单位中间断行

- **所见证据：** [10-today-dark-300.png](evidence/2026-09-07/10-today-dark-300.png) 与 [11-quick-add-dark-300.png](evidence/2026-09-07/11-quick-add-dark-300.png) 的下一步卡片中，“45 分钟”被拆为第一行末尾的“45”和第二行开头的“分钟”。同一个任务在 [09-today-dark-340.png](evidence/2026-09-07/09-today-dark-340.png) 中只占一行。源码也显示该区域把时间、截止、项目、耗时拼成一段 Text。
- **用户影响：** 用户需要跨行重新拼接“45 分钟”，第二行只有单位，还白白增加推荐卡高度。卡片承担首要任务，却恰好在支持的最窄尺寸下失去排版完整性。
- **明确改法：** 把每项元信息作为独立且不在内部换行的单元，让布局只在单元之间折行；“截止 19:00”和“45 分钟”各自完整保留。无需添加胶囊背景。如果仍拥挤，可以把项目放到独立的次要位置，而不是缩小所有字。
- **性质与确定程度：** 可验证的排版问题，确定程度高。这里只确认下一步卡片的该组内容，未声称所有任务元信息都会断错。

## 4. P2 — “全部”页的分组留白成本过高，卡片层级挤占紧凑面板

- **所见证据：** [03-all-light-340.png](evidence/2026-09-07/03-all-light-340.png) 顶部写着 5 件待办，当前视口只完整呈现约前三项，底部刚露出“生活 1”的组标题；每个只有一项的项目仍占一段较大的独立纵向区块。对照 [02-today-light-340.png](evidence/2026-09-07/02-today-light-340.png)，顶部品牌行、大标题、日期、分段导航已占到约 178px，中央区域还包含外阅读面和内推荐卡两级留白。[10-today-dark-300.png](evidence/2026-09-07/10-today-dark-300.png) 中推荐卡的层层内缩进一步放大长标题和元信息折行。
- **用户影响：** 少量任务就需要滚动；“按项目整理”本应提高概览效率，这组数据里却让项目标题与空隙占去更多注意力。圆角容器的存在感超过了任务条目的组织感。
- **明确改法：** 先收紧“全部”页组间间距和组标题到首项的距离，保留分组语义；让单项项目也能紧凑连续地读下去。默认列表行的上下内边距可小幅降低，仍保留 30px 完成按钮命中区。300px 下将推荐卡内边距从 16px 适当减到 12px，避免让窄幅内容承担与宽幅相同的层层留白。外壳可继续圆润，内部阅读面和推荐区的圆角应拉开级差，减少连续套盒的感觉。
- **性质与确定程度：** 首屏容量与折行是可观察事实；“应更紧凑”和圆角级差是基于任务工具用途的品味 / 产品取舍，确定程度中高。这里不主张取消所有留白，也不把正常滚动视作故障。

## 5. P3 — 详情页的泛化标题与任务标题争夺同一级别

- **所见证据：** [04-detail-light-340.png](evidence/2026-09-07/04-detail-light-340.png) 上方“这件事”和卡片内“写完 TodoCue 的产品介绍”都使用大号粗体，分别占据两个标题区。后者才是用户正在查看的对象，前者提供的新信息很少。对应源码字号仅为 23pt 与 22pt。
- **用户影响：** 进入详情后的第一眼先看到一个泛化页面名，再重新定位真正的任务标题。两段近似权重的标题让一个很小的面板有了重复的开场。
- **明确改法：** 详情页保留顶栏返回和工具按钮，把“这件事”降为小号上下文文字或直接省去这行，让任务标题成为唯一主要标题；将释放的高度用于任务内容。编辑页的“编辑任务”具有操作上下文，可以保留。
- **性质与确定程度：** 双标题、字号接近是可验证事实；是否省去“这件事”属于主观层级取舍，确定程度中等，不是功能错误。

## 两项值得保留

1. **下一步的单一焦点与明确完成动作。** [02](evidence/2026-09-07/02-today-light-340.png) / [09](evidence/2026-09-07/09-today-dark-340.png) 中，推荐任务在字号、色相和完成按钮上都能从普通条目中被迅速识别。这比给所有任务同时加多种强调更有价值，应在收紧布局时保留。
2. **Cue 开口圆环与克制的墨绿 / mint 识别。** [01](evidence/2026-09-07/01-installed-empty-light-340.png) 的品牌标记、完成状态和温和文案方向一致，空态没有堆砌插画或装饰。这个母题足以继续发展，不需要为了“高级感”另加复杂图形或更多颜色。

## 一个统一方向

**把 TodoCue 做成一张安静、利落的桌面便笺。** 玻璃负责让面板融入桌面；内部依靠清楚的对齐、语义完整的文字和适量留白组织任务。mint 留给下一步、完成与当前焦点，品牌圆环保持轻量。外壳可以柔软，内容需要更有秩序：少一层套盒感、少一次无意义折行、少一段重复标题，比增加新的视觉效果更能提升这款工具的质感。

本报告只评价静态可见结果。未据此宣称键盘体验、动画流畅度、读屏表现或多种桌面背景下的材质已经验证，也未进行像素级对比度测量。
