# 已完成历史验收记录

2026-09-08。功能：面板内独立的「已完成」页，按完成日期回看做过的事，并能按名字找回某一件。

## 为什么需要

改动前，完成的任务只在两个地方出现：今日面板的「今日已完成」折叠区（只有当天），
以及日历里某一天的日程（一次一天，且按**计划日期**分桶）。
「这周做了什么」「那件事我完成后去哪了」两个问题都没有答案。

## 关键决定：按完成时间，不是计划日期

`listTasks` 的 `from`/`to` 过滤的是 `planDate`（`engine.ts:531-539`、`:549`）。
用一次性 runtime 实测确认：一个计划在 2020-01-01、今天完成的任务，会被 `from=today` 的范围**排除**。
所以范围查询在这里根本不能用。

而服务端已经把非 todo 任务按 `completedAt` 倒序排好（`compareTasks:737`），
`orderTasks:571` 又完全跳过非 todo，所以 `status=done&limit=N` 返回的就是「最近完成的 N 件，最新在前」——
这不是任意截断，是定义明确的窗口。因此**后端零改动**，也不碰 `docs/api.md`。

## 交互

- 入口：头部「更多操作」菜单的「已完成…」，以及今日面板「今日已完成」折叠区上的「查看全部」。
  没有加第 5 个头部图标——300pt 下头部已占 198/256pt。
- 按完成日分组，最新在前；日期跨年时自动带上年份。
- 搜索框过滤**已加载**的集合，并在还有更多时明确说明「只搜索了已加载的 N 件」。
- 「加载更早」每次多取 60 件，上限 1000（`ListTasksQuery.limit` 的 schema 上限），到顶明说。
- 行用 `TaskRowView`：勾选框点一下就重新打开，点标题进详情。

## 对抗性审查修掉的问题

| 严重度 | 问题 | 处理 |
|---|---|---|
| 高 | 探测请求为 `min(window+1, maxWindow+1)`，翻到底时发出 `limit=1001`，而 schema 是 `max(1000)` 且服务端只 parse 不 clamp——最后一页必然 400，按钮永远留着且毫无反馈 | 探测封顶到 1000；到顶时 `hasMore` 明确为 false。抽成纯函数 `probe`/`hasMore` 并按**实际发出的值**逐窗口断言（旧测试只断言了常量，正好漏掉） |
| 高 | 搜索无结果时整个 footer 消失——既看不到「只搜索了已加载的 N 件」，也没有「加载更早」。而「找回三个月前那件事」正是这个页面存在的理由 | footer 移到搜索分支之外 |
| 中高 | 列表非空时的加载失败完全静默：转圈一下，按钮原样返回 | 失败时显示「加载失败」+ 重试 |
| 中 | 离线进入后无法就地恢复——`refreshAll`、`apply` 都不刷新此页 | 空态加重试按钮 |
| 中 | `apply(board)` 不刷新本页，行里的 `version` 会过期；此时点勾选框重开会 409，且每次重试都一样失败 | 本页显示时随 board 刷新 |
| 中 | 拉取在途时完成一个任务，响应落地会把它覆盖掉（丢更新）；插入固定在 index 0，编辑一个窗口外的旧任务会凭空接出一个更早的日期分组 | 在途变更排队重放；按完成时间插入，并拒绝比已加载窗口更旧的任务 |
| 低中 | `reset: true` 在有请求在途时被静默丢弃 | 改为取消在途请求 |
| 低 | 分组用 runtime 时区，而「今天」标题用设备时区判断，两者可能不一致 | 标题也用 runtime 的 today |
| 低 | 抽出 `SearchField` 时，「全部」页的无障碍标签从「搜索任务」变成了占位符全文 | 加 `label` 参数保持原值 |
| 低 | 英文「Searched the N loaded so far」丢了「只」的含义；上限文案不成句 | 重写 |
| 低 | 脚本与证据目录仍叫 calendar，却已覆盖非日历界面；快照测试靠一个会不断变长的排除列表区分场景 | 更名为 `panel-screenshots.mjs` / `2026-09-08-panel`；场景按名字前缀自证跨度 |

审查同时确认：后端排序与 `from`/`to` 的结论属实、分组时区与引擎一致、
`dateLabel` 改写对既有 12 个调用点行为等价（含 DST 边界）、`SearchField` 与原实现逐像素一致。

## 已知边界

- **只收录 `done`。** 已取消／已跳过的任务仍然无处可见——「那件事去哪了」对被取消的任务依然没有答案。
  这是刻意的取舍：本页语义是「已完成」，而勾选框对已取消任务的行为（点一下变成完成）会让人困惑。
  如果要补，应当是一个独立的筛选，而不是混进这里。
- 最多回看最近 1000 件；再往前需要给 API 加按完成时间的查询参数。
- 搜索只覆盖已加载的部分，界面会明说。
- 今日面板的「查看全部」只在当天有完成记录时出现；当天一件都没完成时，入口只有菜单。
- 未真机验证：实际滚动、VoiceOver 朗读。
