# TodoCue 跨平台迁移：实现与验收记录

2026-10-14。当前为可运行的迁移预览，目标是保留 Dial 设计与交互。Windows 实机验收由用户后续进行；完成验收前不切换正式 macOS 客户端，也不宣称四个阶段已经全部交付。后续工作按 [交接任务与继续开发说明](desktop-handoff.md)执行。

## 原生对照与体验修正

以 `apps/macos/Sources/TodoCue` 的 HeaderView、NextCard、TaskRowView、QuickAddView、TaskFormView、TaskDetailView、NotchView，以及实际运行的 SwiftUI 面板作为基准。离屏截图出现 NSGlass/SF Symbols 占位时不用作视觉真值。

共享尺寸来自 `src/tokens.ts`：340 默认宽、14 外边距、42 外壳圆角、28 卡片圆角、10 间距、60 数字、84 表盘、185×24 刘海基体及 44 宽摘要翼。字体继续分发 Michroma 与 OFL。SVG 按原轮廓校准，避免用 Unicode 字符替代系统图标。

已调整头部层级、数字与日期位置、下一步高度、元数据、16 宽拖动柄、26 点击区/18 圆圈、左侧 42 快速添加圆盘、卡片与列表共同滚动、固定底部输入。页面重叠交替而不分摊高度；退出页面停止接收输入。表单属性使用独立浮层、图形日期选择、项目和耗时预设。日历随短窗口折叠为所选周，保留议程空间。

弹簧 response/damping 转为物理参数；刘海宿主用 0.32/0.86 校准窗口边界变化，避免只有内容淡入而窗口突然跳大。减少动态效果时跳过这段运动。新提醒完整展示约 6 秒再收成常驻行，移屏驻留为 1.5 秒；周期提醒只有实际可见的卡片才 claim/receipt，未显示的 offer 留给系统渠道。

视觉比例已进入原生对照迭代，仍需对全部页面、两种语言、明暗主题和 300/340/480/600 宽度做验收。字体抗锯齿、系统玻璃和原生弹层边界差异单独记录；当前未作逐像素一致的承诺。

## 已验证的入口与失败场景

在隔离临时数据上进行了真实 CLI/API/SSE 与 Ego Lite 浏览器操作，验证了 CLI 建任务实时出现、快速输入创建、完成和撤销、任务编辑保存、返回后草稿保留、日历打开详情并返回。

另验证拖动排序与撤销、今日已完成展开后重新打开。中英文首页在明暗主题及 300/340/480/600 宽度下，没有横向溢出，底部输入保持可见；这项检查只覆盖首页，不替代全部页面视觉验收。原生窗口从 340 调整到 400 后，重启保留 400 宽度；Mac 内侧边缘调整宽度、底边 680→620 调整高度，以及双击恢复 340×680 均通过实际操作。Tao 的 macOS 缩放拖动尚未实现，因此此平台使用宿主尺寸桥接，Windows 保留 Tauri 原生路径。

独立审查者在真实保存请求上延迟返回，验证：保存时继续输入；保存中返回并重开同一逻辑草稿，再次输入/保存；快速添加提交后继续输入下一条；完成返回 409 时继续留在详情且显示错误。测试数据没有写入个人生产目录。

自动检查覆盖便携客户端、真实引擎的精确时间保留/改期、提醒去重与 claim 可见性、草稿保存快照、Windows 注册失败后重试、被占用 CLI 不覆盖、发布原生版本与 lock 同步、隔离打包布局、现有 CLI/MCP 冒烟及 Swift 测试。三个 Windows helper 通过了隔离的 x64 目标类型检查；完整 Windows 宿主 cross-check 被本机缺少 Windows SDK 的 `assert.h` 阻断。因此不把 macOS 编译或 helper 类型检查当作 Windows 安装/运行验收。

已通过 `npm run check`（160 个 Vitest、19 个发布/打包脚本测试和 CLI/MCP 冒烟）、Rust 16 个测试、Swift 275 个测试（其中 4 个跳过）；共享前端 TypeScript/Vite 构建与 macOS Preview app 打包成功。测试覆盖的范围与尚未完成的交互验证见交接文档。

### 截图反馈与刘海交互

macOS 虚拟刘海改为位于屏幕顶部，使用菜单栏高度，窗口层级为 `NSStatusWindowLevel + 1`；Windows 仍按工作区顶部定位。原生截图确认收起窗口为 273×30 逻辑像素，布局测试覆盖平台差异及顶部/侧边任务栏；真实硬件刘海、安全区及多屏行为仍待验收。

刘海快速输入改为 36 高的圆角胶囊，焦点描边由容器绘制，移除输入元素的橙色矩形 outline；面板快速输入、搜索和表单正文也移除不符合原生对照的矩形 outline。字体、图标、尺寸与动效仍需逐页校准，不能仅凭这次调整宣称 UI 已与 SwiftUI 一致。

macOS 安装 AppKit 本地与全局鼠标监听；点击其他窗口时收起快览并保留草稿。已用另一应用窗口的实际坐标点击验证收起，重新展开后草稿仍在；提醒堆叠不因外部点击被清除。避免把原生失焦直接等同于外部点击，以减少输入法候选窗口或焦点变化导致的误收起。

原生自动化输入验证过程中仍观察到快览提前收起，回车创建尚未在最终原生包中验证成功。暂未确认是自动化激活/窗口定位还是实际焦点行为，需要接手者首先复现并修正；先前浏览器创建通过不能替代这项原生验收。临时鼠标诊断输出已清理。

### 审查发现的八项修复

| 失败场景 | 修复与证据 |
| --- | --- |
| 临时 `TODOCUE_HOME` 启动后，安装器无法停止自定义目录的服务 | 当前用户目录 `%LOCALAPPDATA%\\TodoCue\\homes` 持久化安装路径与数据目录关联；无原 shell 环境的升级/卸载模拟覆盖两个自定义目录，并保留其他安装的服务 |
| 四条周期提醒同时领取，第四条无法展示且失去系统投递 | 在第一次异步操作前预留三行容量，直到回执完成；真实引擎验证第四条保持未领取，并在 offer 超时后通过系统渠道投递；领取期间任务到达不挤走未回执行 |
| 保存过程中移除上传附件，保存返回后附件复现 | 以提交顺序和原附件 ID 对应新增附件，把期间移除的上传转为下一次写入的移除 ID；覆盖新建、编辑、同名同内容文件，浏览器实际延迟保存后的第二次写入确认附件为空 |
| 重新打开两条已完成任务，旧查询响应又恢复已完成行 | 事件、重连与操作触发的历史刷新共用请求代次；浏览器保留两个含 B 的旧响应，先重新打开 A/B 再放行响应，界面为空且后台两条任务均为 todo |
| 日历拖到同日但晚于截止时间，跳过确认 | 在任务时区中计算实际改期瞬间，确认与写入使用相同时间；覆盖 UTC、上海、纽约夏令时；浏览器实际拖动 18:00 任务到次日 17:00 截止日，确认前数据不变，确认后保留截止时间 |
| 改变服务端口后仍由旧宿主继续运行 | 更新注册和清单前停止已注册任务，等待计划任务状态及宿主互斥释放；模拟异步退出验证旧清单不提前覆盖、新宿主采用新端口，停止失败不替换、注册失败恢复旧服务 |
| 自定义目录通知冷启动进入默认目录 | 通知 URI 携带已登记目录的短标识，宿主验证归属后选择目录；每个目录独立处理热启动，避免进入别的数据或丢弃草稿；未知标识不回落到默认目录，token 和原始目录路径不放入 URI |
| 产品卸载留下不可用的 CLI 与 PATH | 产品卸载按运行时指针归属清理 CLI、指针、受管理 PATH、UI 登录启动项和服务关联；保留数据库、备份以及其他安装的集成；单独 `service uninstall` 保留 CLI |

安装器同时区分普通卸载与更新/维护替换；连续两次停止保留恢复标记，更新后恢复原本运行的服务。分支已按当前 Tauri CLI 2.12.2 的 [NSIS 模板源码](https://github.com/tauri-apps/tauri/blob/tauri-cli-v2.12.2/crates/tauri-bundler/src/bundle/windows/nsis/installer.nsi)核对，未在 Windows 上执行安装器。

复测还修复了开发代理未转发 DELETE 请求体长度的问题；真实 Vite→HTTP→运行时测试验证任务与附件删除均收到版本参数。Windows 登录启动命令为可执行文件与自定义目录保留引号，覆盖含空格和末尾反斜杠路径。

本轮三个 helper 的最新源码分别通过 x64 与 ARM64 Windows 目标的隔离类型检查；目录路由和通知 URI 也有 Rust 回归测试。这些检查不等于 Windows 通知点击、计划任务退出及 NSIS 安装实测。

## Windows 实机验收

从对应架构的 preview 安装包开始，先使用独立 `TODOCUE_HOME` 做下列流程。Windows 10/11 x64 和 Windows 11 ARM64 分别记录结果。

1. 干净机器不另装 Node，离线安装 WebView2 后启动；CLI `context`、创建、完成、附件读写与 MCP stdio 正常；ARM64 核对 Node/SQLite/通知助手原生运行。
2. CLI 建任务 → 面板实时出现 → 面板完成并撤销 → 提醒到时出现刘海。鼠标悬停不抢焦点，固定后能输入中文，Esc 先清输入再收起。
3. 100%、125%、150%、200% DPI，多屏不同缩放、屏幕负坐标、顶部/侧边任务栏；检查定位、透明圆角外的桌面点击、拖动、插拔及睡眠恢复。
4. 全屏、虚拟桌面切换、显示器重新排列后的定位和安静策略；此项需要实际系统检查并按结果修正宿主。
5. 多任务/周期提醒堆叠、×N、6 秒收拢、暂停/稍后、休眠后的补偿；验证已 receipt 的周期提醒没有额外系统投递，未显示的 offer 能回退。
6. 关闭面板以及从托盘退出全部 UI 后仍通知；点击通知冷启动/热启动都进入目标，后台尚未就绪时目标保留到连接恢复。
7. 升级前停止旧运行时，升级/重装/卸载保留数据库；注册失败能重试，重复启动不同时占用数据目录；原 CLI 与新 CLI 没有标准输入输出污染。
8. 全部页面的语言、主题、长标题、空/加载/离线/冲突状态；表单输入、文本选择、附件粘贴/选择/预览、拖动跨项目/日期与撤销；逐帧录制完成、切页和刘海展开。

## Windows 验收后再做的 macOS 迁移

- 真实硬件刘海、安全区、菜单栏、空间切换与原生浮窗行为的完整桥接。
- EventKit 同步从旧 UI 模型解耦，接入共享客户端；保留既有同步关联。
- 导入旧语言、窗口尺寸、快捷键和同步偏好，沿用生产数据目录。
- 单一生产客户端切换、旧包回退；达到功能和视觉验收后才停止维护 SwiftUI 页面。

当前 macOS Preview 已采用 macOS 菜单栏定位，但仍只承担虚拟刘海预览；不承担真实硬件刘海或 Apple 同步验收。
