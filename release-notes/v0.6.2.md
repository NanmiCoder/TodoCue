# TodoCue v0.6.2

v0.6.1 之后的修复版本：修复 macOS 刘海屏上，双击其他软件的标题栏把窗口铺满后，TodoCue 的刘海消失的问题。任务引擎、REST API、CLI、MCP 和数据库格式没有变化，数据目录与 v0.6.1 兼容。

## 下载与安装

- macOS 14+：Apple Silicon 选择 `macOS-arm64.dmg`，Intel 选择 `macOS-x64.dmg`。将 TodoCue.app 拖入 Applications，退出旧版后打开。两个 DMG 均经 Developer ID 签名、Apple 公证及 stapling 验证。
- Windows：x64 选择 `Windows-x64-setup.exe`（Windows 10/11），ARM64 选择 `Windows-arm64-setup.exe`（Windows 11）。Windows 安装包未做 Authenticode 签名，系统可能显示未知发布者；请只从本仓库 Release 下载，并核对 SHA256SUMS。
- 从 v0.6.1 升级：直接用新安装包覆盖安装，数据保留。

## 本版变化

- **刘海屏上缩放铺满的窗口不再让刘海消失**：在带摄像头刘海的 MacBook 上，双击其他软件的标题栏（缩放）把窗口铺满后，窗口顶部正好贴着菜单栏下沿，边界与原生全屏窗口完全相同，旧版据此误判为「全屏」而静默刘海，必须把窗口往下拖出一点间隙才会恢复。现在窗口顶部低于屏幕上沿时，还要求当前活动 Space 是原生全屏 Space 才静默刘海；缩放窗口下刘海正常显示，原生全屏下仍保持安静。

## 升级、边界与回退

默认数据仍在 `~/.todocue`（Windows 为 `%USERPROFILE%\.todocue`），支持 `--home` / `TODOCUE_HOME`。旧的 SwiftUI 客户端运行时，通用版会提示先退出，避免同时操作同一份数据。

本版仍不提供旧 SwiftUI 客户端的 Apple 日历/提醒事项同步、硬件刘海安全区适配及全部偏好自动导入。依赖这些功能的用户可继续使用 v0.5.3，使用同一数据目录即可恢复旧客户端。

本次修复在内建刘海屏（1728×1117）上用自建测试窗口依次切换普通、缩放、原生全屏和恢复四种状态验证：缩放时刘海显示，原生全屏时静默，恢复后显示。尚未用第三方 App 的真实全屏逐一验证，也未在刘海屏加外接屏的多屏环境验证（判断依据是主显示器的活动 Space，多屏下可能与刘海所在屏不一致）；窗口顶部在摄像头区下方、却不是原生全屏的「传统全屏」窗口，刘海现在会显示。依赖私有的 Space 类型接口（运行时查找，缺失时退回旧行为）。Windows 的判断逻辑没有改动。Windows 的 GUI、多屏/DPI/休眠/通知点击等硬件验收仍保留，详见 [迁移交接](https://github.com/NanmiCoder/TodoCue/blob/main/docs/desktop-handoff.md)。
