# TodoCue v0.10.3

修复 Windows 首次打开后无法连接后台的问题，并恢复更容易使用的面板拖动区域。任务引擎、REST API 和数据库格式保持兼容。

## 本版变化

- **Windows 后台自动启动。** 修复 Tauri 的 Windows 资源路径与内置 Node 26 不兼容，导致后台在加载入口文件前退出的问题。App 打开后会正常初始化本机后台服务。
- **离线重试可恢复后台。** 面板和托盘的重试会重新执行后台初始化，再加载任务；初始化失败的原因保存在数据目录的 `logs/desktop-bootstrap.log`。
- **面板拖动与外框。** 顶部 TodoCue Logo、应用名称和空白区域均可拖动窗口；标题栏按钮仍正常点击，任务标题和备注仍可选择文字。Windows 面板关闭额外的原生无边框阴影，并补齐尺寸手柄权限。
- **首次启动回归检查。** Windows 安装验证现在先启动真实 GUI，再检查后台健康，避免先运行 CLI 安装掩盖 App 启动故障；另增加实际 Node 子进程的 Windows 路径回归测试。

## 下载与升级

- macOS 14+：Apple Silicon 选择 `macOS-arm64.dmg`，Intel 选择 `macOS-x64.dmg`。退出旧版，将 TodoCue.app 替换到 Applications 后重新打开。正式 Mac 包通过 Developer ID 签名及 Apple 公证。
- Windows 10/11 x64 选择 `Windows-x64-setup.exe`；Windows 11 ARM64 选择 `Windows-arm64-setup.exe`。Windows 安装包未做 Authenticode 签名，请从本仓库 Release 下载并核对 `SHA256SUMS`。
- 覆盖安装保留数据。默认目录仍为 `~/.todocue`（Windows 为 `%USERPROFILE%\.todocue`），可继续使用原有 `TODOCUE_HOME`。Windows 与 macOS 各自使用本机数据目录。

## 验证与边界

Windows 本机已复现资源路径导致的 Node 启动失败，修复后独立目录的 GUI 冷启动能够初始化后台；共享前端已验证新增任务、后台保存、重新加载后的读取，以及最小宽度下的标题栏按钮布局。原生外框、实际鼠标拖动和尺寸手柄仍未完成自动化实机验收。[验证记录与共享前端截图](../docs/qa/windows-startup-ui/README.md)

正式发布流水线在四种架构的构建、安装回归及校验和检查全部通过后发布安装包；这些检查不替代上述原生 UI 验收。
