# TodoCue v0.7.1

v0.7.0 之后的修复版本：修复外接屏等没有摄像头的 Mac 屏幕上，收起的刘海挂在菜单栏下方的问题。任务引擎、REST API、CLI、MCP 和数据库格式没有变化，数据目录与 v0.7.0 兼容。

## 下载与安装

- macOS 14+：Apple Silicon 选择 `macOS-arm64.dmg`，Intel 选择 `macOS-x64.dmg`。将 TodoCue.app 拖入 Applications，退出旧版后打开。两个 DMG 均经 Developer ID 签名、Apple 公证及 stapling 验证。
- Windows：x64 选择 `Windows-x64-setup.exe`（Windows 10/11），ARM64 选择 `Windows-arm64-setup.exe`（Windows 11）。Windows 安装包未做 Authenticode 签名，系统可能显示未知发布者；请只从本仓库 Release 下载，并核对 SHA256SUMS。
- 从 v0.7.0 升级：直接用新安装包覆盖安装，数据保留。

## 本版变化

- **没有摄像头的屏幕上，刘海放进菜单栏的空位**：外接屏上菜单栏图标常常越过屏幕中线，旧版为了不盖住图标，只能把刘海挂在菜单栏下方。现在 TodoCue 读取菜单栏图标的位置（不需要屏幕录制权限），把刘海贴住屏幕顶边、高度等于菜单栏、宽度与内建屏刘海相同：
  - 中间空着就居中；中间被占时，放在离中心最近、与图标相隔 8 点的空位；放不下时才退回菜单栏下方。
  - 被图标往左挤时，不进入左侧 640 点的应用菜单保留区。
  - 位置仍放得下、最佳位置又只差 24 点以内时不动，所以托盘数字等图标宽度的小变化不会让刘海跳动；新图标出现或图标消失时它会让位。
  - 展开、收起和动画期间位置不变，缩回原尺寸后才移动；快览和提醒堆叠以刘海为中心展开。
  - Ice、Bartender 等菜单栏整理工具的超长空状态项只算右端，不会让刘海一直退回下方。
  - 找位置只移动刘海，不会重设你刚调好的面板尺寸。
- **设置页预览**：没有摄像头的 Mac 屏幕上，“顶部”的预览把刘海画在菜单栏条内，提示文字同步说明。带摄像头的屏幕和 Windows 行为不变。

## 升级、边界与回退

默认数据仍在 `~/.todocue`（Windows 为 `%USERPROFILE%\.todocue`），支持 `--home` / `TODOCUE_HOME`。旧的 SwiftUI 客户端运行时，通用版会提示先退出，避免同时操作同一份数据。

本版仍不提供旧 SwiftUI 客户端的 Apple 日历/提醒事项同步、硬件刘海安全区适配及全部偏好自动导入。依赖这些功能的用户可继续使用 v0.5.3，使用同一数据目录即可恢复旧客户端。

菜单栏避让的验证与限制：

- 已在一台 Mac 的两块外接屏上实测：静止时紧挨图标；托盘出现数字后约 0.4 秒内让位；临时加入一个 80 点宽的图标后退回菜单栏下方；提醒堆叠展开和收起时位置不变；第二块屏幕中间空着时居中。
- 前台应用的菜单宽度在没有辅助功能权限时读不到，640 点是经验值（实测 22 个应用中最宽的菜单到 594 点）。菜单更长的应用（Xcode、Office 等）未测，仍可能被盖住；屏幕窄于约 1509 点时，居中的刘海也会落入这个区间。
- 菜单栏图标多时，刘海会退回菜单栏下方，位置与旧版相同。
- Ice / Bartender 只有单元测试；菜单栏自动隐藏、“显示器使用独立空间”关闭、带摄像头的内建屏、悬停展开后快览位置的原生验证未做。
- Windows 与 Linux 不进入这套逻辑，只审查了代码；Windows 的 GUI、多屏/DPI/休眠/通知点击等硬件验收仍保留，详见 [迁移交接](https://github.com/NanmiCoder/TodoCue/blob/main/docs/desktop-handoff.md)。

详细记录见 [docs/qa/notch-display](https://github.com/NanmiCoder/TodoCue/blob/main/docs/qa/notch-display/README.md)。
