# 面板只读界面渲染证据（2026-09-08）

覆盖日历、已完成历史，以及守住三段控件外观的今日面板。

由 `node scripts/panel-screenshots.mjs <输出目录>` 生成。脚本在临时 `TODOCUE_HOME` 里起一个
一次性 runtime 并写入示例任务，用户真实的 `~/.todocue` 不被读取或修改。

渲染走 `ImageRenderer` 离屏输出（`CalendarSnapshotTests`），不开窗口、不抢焦点、不占用指针。
代价是 `ImageRenderer` 会把 `ScrollView` 布局成零高度，也画不出任何 `NSViewRepresentable` ——
`Menu`、`TextField` 的 placeholder、拖拽握把、拖放区域都会变成黄色禁止符占位块。因此：
整页图里日程区是空的、头部菜单与底部快速输入框是占位块；任务行左侧的握把也是占位块；
`month-dragging` 整张网格都是占位块，因为拖放区域只在拖拽进行中挂载，而那正是这一帧。
日程区与周视图另外以 `-agenda-*` / `-week-bare*` 脱离滚动容器单独渲染，文字仍然可读。

测试内置两道自检：每个 `month-*` 场景断言 `calendarSpan == .month`，并且所有输出两两不得字节相同。
这两道是补上的 —— 第一版证据里 `showCalendar()` 没有重置跨度，导致所有月视图截图其实渲染的是周视图。

示例数据：今天一件、两天前一件逾期、六天前一件已完成、明天计划且 5 天后截止一件、
62 天后一件（远超 30 天预生成范围）、每日重复一条、每周一三五重复一条。
