# TodoCue 原生 UI 优化与实际验收

后续的 macOS 26 Liquid Glass 整体重构见 [设计说明与验收](design/liquid-glass.md)。下文保留此前各轮验收记录。

日期：2026-09-07。基线：`d5551ef`。本轮针对现有 macOS 客户端优化，并使用隔离数据进行原生 UI 验证。

## 实际问题与修改

- 原版重点任务同时出现在下一项卡片和逾期分组；今日计划又重复显示“今天”和“今日计划”。现在今日只显示一份重点任务，保留总数，去掉空分组及重复标签；未来和全部列表仍完整显示任务。
- 日期/剩余数量层级弱、页签未铺满、辅助信息拥挤。保留 380×680 基线与系统字体，改成等宽固定页签、18pt 日期、14pt 任务、12pt 辅助信息、统一按钮目标和更清楚的分组间距。逾期文字/期限用可读的暖色，项目与耗时保持次级颜色。
- 标题原来单行、多个属性挤在一行。表单按内容、属性、时间安排分区，支持多行标题，日期开启后再显示输入与原生日历，重复时间/提醒各自成行。保存区和校验提示固定在滚动区外，⌘Return 保存。
- 左上返回直接丢弃草稿，而 Esc 保存草稿。统一返回、Esc、⌘F 等导航的草稿保护；继续编辑同一任务恢复草稿。移除对每次草稿变化的整页动画。
- 快速添加原来立即清空文本且新任务不属于今天。明确“添加到今天”，请求成功再清空，输入跨导航保留，重复提交被阻止。
- 完成按钮原来延迟提交、允许重复点击。改为真实请求期间禁用，成功后显示 10 秒撤销提示；提示不覆盖输入。撤销仍调用现有引擎，不补发过去提醒。
- “明天”原来对多日前的具体时间只加一天，有时依然逾期。改为相对当前日的明天，保留时刻/日期精度，移动今天及已过的截止时间，保留未来截止日期。
- 用户在 Computer use 中反馈抢焦点及失焦隐藏：移除 `NSApp.activate(ignoringOtherApps:)` 和外部点击关闭监听；采用 `.nonactivatingPanel`，普通展示不请求键盘，仅编辑入口请求。默认失焦保持显示，× 关闭，固定按钮防止根页面被 Esc 误收起。
- 修复显示/关闭动画的过期回调可能关闭重新打开窗口；监听材质/降低透明度变化。刘海去重并最多显示 3 个任务，总高度上限 300pt，补充本应用鼠标移动监听，侧栏打开时禁止再自动展开快览。

## 可变宽度面板追加验收（2026-09-07）

本次将上述固定 380pt 宽度改为默认 340pt、可调 300–600pt。左边缘增加 10pt 命中区与细条，拖动时保持右边缘位置，双击恢复默认；窗口原生边缘也支持调整。用户宽度写入 macOS 应用偏好，临时屏幕适配不覆盖该偏好。高度保持原有规则。

任务标题最多显示三行、辅助信息两行；详情长字段完整换行。详情操作、状态、表单优先级/耗时、日期/时间、设置操作采用可换行布局。布局切换保留控件身份与输入焦点。实际测试发现 SwiftUI 活跃多行输入框的文本容器保留旧宽度，已同步修正容器宽度，避免拉宽后旧换行被裁切。

- `swift test --package-path apps/macos`：33 项通过，新增 6 项覆盖宽度边界、屏幕内约束、右边缘固定、偏好恢复、双击恢复默认，以及活跃文字重排/选区保留。
- CUA 原生实测：隔离预览在 300、340、520pt 下查看列表、长中文详情、编辑表单、日历弹层与设置。优先级/耗时在窄窗口分行；300→520→300 拖动时长标题重排，选区保持。退出并重开预览恢复 520pt。示例数据在 `.ui-review/width-home`，使用 MemoryNotifier，不发送真实通知；预览与测试 Runtime 已停止。
- `npm run macos:dmg`：通过。Developer ID 签名与内置 Node/SQLite/MCP 加载检查通过；DMG 挂载校验和通过。
- 已从新 DMG 更新 `/Applications/TodoCue.app`。正式版重新连接原数据库，实测编辑中 340→520→340 拖动正确，重启恢复 340pt。只查看原任务并进入编辑，没有提交修改。更新前后任务内容/状态/版本与认证信息指纹一致，后台健康检查通过。
- `git diff --check`：通过。测试日志保存在 `.ui-review/width-swift-tests.log`、`.ui-review/width-dmg-build.log`。

## 刘海真机验收（2026-09-07）

机器为 16 英寸 MacBook Pro 内建屏（1728×1117pt，刘海 185×32pt）。验收使用调试构建，通过合成鼠标事件与 Accessibility API 驱动，任务数据为本机运行时。

- 收起态窗口 293×32pt，与系统报告的刘海矩形同中心：左翼 Cue 标记、右翼今日剩余数，与刘海融为一体。
- 悬停 0.2 秒展开为 560×286pt（一条下一步任务时），离开 0.35 秒后收起；展开高度来自 `onGeometryChange` 的实际测量（222→168→254pt 随数据加载变化），底部输入框和内边距完整可见。此前 PreferenceKey 方案在该窗口内收不到尺寸，窗口停在 220pt 兜底高度，输入框被裁掉，已改用几何回调。
- 点击刘海：展开并固定，面板成为键盘焦点（`AXFocusedUIElement` 为快速添加输入框）但 TodoCue 未激活。键入“刘海快览测试”并回车，运行时立即出现该任务，卡片长高到 346pt 并显示新行。
- 通过 Accessibility 按“完成 刘海快览测试”后运行时状态为 `done`，卡片收回 286pt 并出现“已完成…撤销”提示；按“撤销”后状态回到 `todo`。
- Esc 后窗口回到 293×32pt，TodoCue 的焦点元素与焦点窗口均为空，键盘交还给原来的 App。验收任务已取消。
- 合成事件下全局 `mouseMoved` 监听在菜单栏区域收不到事件，因此在刘海窗口上加了 `NSTrackingArea`，进入黑条即开始轮询；真实鼠标与合成鼠标均可触发。
