# 提醒常驻与堆叠

2026-10-12。周期提醒从刘海落下后 9 秒就收起，没看到就过去了。改为：落下之后一直留在刘海，直到用户完成、延后、今天暂停，或运行时判定它已失效。多条同时等待时叠在同一个堆叠里。

设计探索画布（8 块，含可操作原型）：<https://claude.ai/artifact/26CRPksx2nagtEmErYEHgA>。用户在画布上逐项确认「全按推荐」。

## 已定的方案

| 编号 | 问题 | 方案 |
| --- | --- | --- |
| D1 | 单条常驻的形态 | 落下时整卡约 6 秒（波纹与 Cue 标记动画与原来一致），之后在原地收成一行，不再靠时间消失。只有一条时，指针悬停会原地展开为整卡，露出「今天暂停」 |
| D2 | 多条排布 | 上下堆叠，最多 3 行，第 4 件起折叠为「还有 N 件」并通向快览。任务提醒在上，周期提醒在下，同层按到达先后；位置不因他人到来或离开而改变 |
| D3 | 任务提醒是否也常驻 | 是。与周期提醒进同一堆叠，完成、10 分钟后或收起才离开。任务本身不受影响，系统通知通道不变 |
| D4 | × 的含义 | 把整个堆叠收进刘海左翼，显示数量；不改变任何提醒状态。新提醒到来或规则回到时段内时重新展开。快览顶部的「待你回应」分区可直接处理 |
| D5 | 放着不管 | 翼标每 5 分钟放出一圈波纹，不再弹出整卡 |
| D6 | 时段结束、午休 | 规则离开时段后，它的行退场；回到时段内，以整卡再落一次，并计一次「×N」。当天最后一个时段结束后不再出现，次日由引擎重置 |
| D7 | 多屏 | 堆叠跟随指针所在的屏幕；指针在另一块屏上停留满 1.5 秒才迁移。新提醒到来时立即落在指针所在的屏幕 |

## 行为细节

- **一规则一行。** 行以任务或规则为键。同一条规则在回应前再次触发（固定时间点到了下一个点，引擎让上一次作废、换成新的一次），原行更新并累加「×N」；位置不动。
- **回应前不离开。** 行只在以下情况离开：用户完成/延后/今天暂停并且运行时确认；运行时报告它已不是当前的（别处完成、暂停、删除、延后、编辑规则）。回应请求在途时行保持忙碌；失败时行留下并显示原因 12 秒。
- **点别处不会收起。** 点击其他 TodoCue 窗口、切换 Space、打开面板都不收起堆叠。点击刘海本身（堆叠顶部不含控件的黑色区域）或标题栏的「今天」会打开快览。
- **不抢位。** 指针正在堆叠上时新来的提醒不立刻插队（避免点错行）；它在标题栏显示「+N 条新提醒」，指针离开后入列。同一规则再次触发只更新原行，不排队。
- **重启与重连。** 运行时里仍处于已展示、未回应状态的规则，在 App 启动或重连后重新出现，不需要新事件。这要求 App 启动时总是加载周期规则列表（此前仅在打开管理页后加载）。
- **全屏与静音。** 与原有设置一致：在全屏应用前台且开启「全屏时不显示」时，堆叠不展开，只在翼标上显示数量，离开全屏后恢复。周期提醒仍然只在能立刻展示时才认领，否则走系统通知。

## 没有改变

引擎的调度、轮次、合并和失效规则，HTTP API，CLI / MCP / Skill 的命令，系统通知降级通道；「已展示」与「已完成」仍分开记录。

## 实现位置

- `ReminderCue.swift`：`CueStack`（按键合并、排序、容量、时段内外），取代旧的串行 `ReminderCueQueue`。
- `NotchController.swift`：堆叠的展示、定时维护（失效清理、时段、延迟入列、翼标波纹、跨屏停留）、回应与重建。
- `NotchStackView.swift` / `NotchReminderView.swift`：行、整卡、「待你回应」分区；`NotchView.swift`：翼标计数。
- `PeriodicReminder.isActive(at:)`：与运行时 `periodicIsActive` 同一规则（周一为 1、起点含终点不含、规则自己的时区）。
