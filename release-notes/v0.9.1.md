# TodoCue v0.9.1

v0.9.0 之后的修复版本：提醒的系统通知更不容易漏。通知失败后不再几十秒就放弃，编辑任务不再让同一条提醒弹两次，通知没开或看不见时界面会主动告诉你。任务引擎、数据库格式没有变化，数据目录与 v0.9.0 兼容；REST API 只新增了字段和一个路由。

## 下载与安装

- macOS 14+：Apple Silicon 选择 `macOS-arm64.dmg`，Intel 选择 `macOS-x64.dmg`。将 TodoCue.app 拖入 Applications，退出旧版后再打开。两个 DMG 均经 Developer ID 签名和 Apple 公证，并已 staple 公证票据。
- Windows：x64 选择 `Windows-x64-setup.exe`（Windows 10/11），ARM64 选择 `Windows-arm64-setup.exe`（Windows 11）。Windows 安装包没有做 Authenticode 签名，系统可能提示"未知发布者"；请只从本仓库的 Release 下载，并核对 SHA256SUMS。
- 从 v0.9.0 升级：直接用新安装包覆盖安装，数据会保留。

## 本版变化

- **通知失败后会继续重试**：以前通知发不出去（例如通知被关、刚登录系统通知还没就绪），只重试 3 次、约 1 分钟就永久放弃。现在按 30 秒、2 分钟、5 分钟、之后每 15 分钟重试，到提醒时间后满 24 小时才算失败；恢复后发出的提醒标题会带"错过的提醒"。启动、睡眠唤醒、重新允许通知时，最近 24 小时内失败的提醒会自动补发。
- **编辑任务不再让提醒重复弹出**：提醒已经响过之后，再改标题、备注等，不会再弹第二次。改提醒时间本身仍会生成新的提醒。
- **通知没开或看不见时，面板里会提示**：未授权、被拒绝、通知样式被设为"无"、有提醒发送失败或正在重试、通知程序缺失，面板顶部会出现一条提示和对应操作（允许通知 / 打开系统设置 / 重新发送）。设置页的通知页也会如实显示"已授权，但不会显示"，并列出最近失败的提醒，可以一键重发。
- **首次启动会主动请求通知权限**：以前要自己去设置页点一下，否则新装后提醒不会弹出。现在只请求一次，拒绝后不会反复打扰。
- **macOS**：未授权或通知样式为"无"时，通知程序会如实报告失败（以前会假装成功）；系统设置里的名称改为"TodoCue"（原来是"TodoCueNotifier"）；通知上点"完成 / 稍后提醒"失败时会打开任务面板，不再毫无反应；使用自定义数据目录时，点击通知会连到正确的目录。
- **Windows**：发送通知前自动检查并注册应用标识，不再依赖安装器是否成功写入；提醒改为带"打开 / 关闭"按钮、保留 24 小时的常驻通知，样式被系统拒绝时自动退回普通通知；发送后会核对通知是否真的进入系统。
- **诊断**：`todocue doctor` 新增提醒投递状态检查，调度器停摆会报错；新增 `POST /v1/reminders/retry-failed`。

## 升级与边界

- **旧的失败提醒不会补发**：超过 24 小时的失败提醒保持失败状态，不会在升级后突然一起弹出。仍可用 `todocue reminders --status failed` 查看。
- **专注模式 / 勿扰仍然会压住通知**：应用无法检测专注模式。使用专注模式时，请在允许的应用里加入 TodoCue。
- **macOS 上系统设置里的名称**：升级后可能要退出并重新打开"系统设置"才会显示新名称；通知授权按应用标识保留，不需要重新授权。
- **Windows 通知图标**：新版不再写指向程序文件的图标，通知上暂时可能不显示 TodoCue 图标。
- **尚未在真机上验证**：macOS 全新账户上授权"未决定"时的实际行为、专注模式下的表现。**Windows 上的全部新通知行为（应用标识自注册、常驻通知样式及其回退、历史核对、安装/升级/卸载钩子）只做了类型检查和单元测试，没有在 Windows 上运行过，请把它当作尚未验证。**

默认数据仍在 `~/.todocue`（Windows 为 `%USERPROFILE%\.todocue`），支持 `--home` / `TODOCUE_HOME`。旧的 SwiftUI 客户端仍可用 v0.5.3 回退，指向同一个数据目录即可。
